第二版原型设计方案

第二版目标是在第一版“摆摊卖苹果”的快感闭环上，补齐可持续经营的基础系统： 日循环、房屋、格子背包、动态农田、商品配置、升级、城管追逐风险和更清晰的程序架构。

Prototype V2 主程序设计文档 Godot 4.6 32x32 Tile 节点 / 信号 / 配置驱动优先 目标：完成全玩法设计与验证

设计原则

收获与售卖是核心

第二版所有系统都服务于“劳作获得货物，再把货物卖出去”的快感。种植、进货、背包、定价、顾客和城管都应该让卖出商品更有紧张感和成就感。

程序先行，美术占位

当前阶段由主程序推进系统。缺少正式美术资源时，使用文字、简单图块或已有占位素材，不在本阶段生成新美术。

节点化实现

优先使用 Area2D、CollisionShape2D、StaticBody2D、Timer 和信号表达规则，避免不必要的逐帧距离判断。

本文档描述第二版原型当前应遵循的设计，不再以旧版“固定农田、发现即罚、只卖苹果”的方案为准。

玩家日常循环

1. 起床从屋内开始，查看昨日总结、现金、时间和背包。
2. 劳作在院子里开垦、播种、浇水，或去小卖部补货。
3. 摆摊去镇街任意可摆摊区域开摊、定价、上架商品。
4. 交易与风险顾客被摊位影响范围吸引，城管发现摊位后追玩家。
5. 回家睡觉睡觉或午夜强制日结，推进作物成长并刷新商店货物。

时间规则

  • 游戏时间从每天 06:00 开始。
  • 1 游戏分钟等于真实 5 秒。
  • 到 24:00 自动进入第二天，没有额外惩罚。
  • 玩家也可以在床上交互睡觉，主动结束当天。
  • 日结显示收入、卖出商品数、接待顾客、拒绝/错过顾客、城管次数和罚款。

场景结构

Main 游戏入口，持有玩家、相机、HUD、背包、商店、定价、结算 UI 和时间 Timer。负责加载 HouseScene、HomeScene、TownScene。
HouseScene 玩家屋内场景，包含床 Bed 和出门入口。床交互触发 GameState.end_day()。
HomeScene 家门口和院子。包含 FarmField 可开垦区域、去镇街入口、进屋入口。旧的固定 FarmPlot 已移除。
TownScene 镇街，包含居民区、学校、工厂、小卖部、顾客生成器、城管生成器和可摆摊区域。

核心系统

全局状态与配置

ConfigLoader 读取 configs/items.json、configs/crops.json、configs/upgrades.json。商品、作物和升级数据优先配置驱动。
GameState 记录现金、日期、时间、当前工具、升级等级、每日统计、商店价格库存、动态农田状态和原型完成状态。
SignalBus 集中转发跨系统信号，如背包变化、现金变化、场景切换、定价面板、日结、工具变化、城管处罚等。

背包系统

  • 背包是格子制，支持同物品堆叠。
  • 每个物品的堆叠上限来自 items.json。
  • 保留 get_count()、add_item()、remove_item() 兼容接口，方便旧系统继续调用。
  • 按 B 打开背包面板，当前版本只查看物品和空格子，不做拖拽整理。
  • 背包升级由 upgrades.json 决定格子数和价格。

商品与作物配置

  • items.json 描述物品名称、分类、堆叠上限、基础售价和图标路径。
  • crops.json 描述种子、收获物、成长天数、产量范围、是否需要浇水和施肥加成。
  • 第二版建议作物控制在苹果、白菜、黄瓜、番茄、梨、土豆。
  • 如需苹果“一浇水就成熟”，可把苹果的 growth_days 改为 0，并在 FarmPlot 浇水逻辑中让该配置立即进入 ready。

农田系统

当前设计

  • FarmField(Area2D) 表示可开垦区域。
  • 只有当前工具是锄头时，FarmField 才加入 interactable 组，避免抢走播种、浇水和收获交互焦点。
  • 玩家站在可开垦区域内按 E，按 TileMapLayer 的 32x32 tile 中心生成一个 FarmPlot。
  • 新生成的 FarmPlot 是 1x1 tile 面积，初始状态直接是 tilled，下一步就是播种。
  • 旧的场景内固定 FarmPlot 已删除，scenes/farm_plot.tscn 只作为运行时生成模板。

状态机

tilled已开垦，等待用种子播种。
seeded已播种，等待用水壶浇水。
watered已浇水，睡觉进入第二天时推进成长。
ready成熟，使用镰刀收获作物进入背包。

持久化规则

  • 开垦时保存 plot_id、cell_x、cell_y、created=true 和状态到 GameState.farm_plot_states。
  • 切到镇街再回家时，FarmField 会根据保存数据恢复动态农田。
  • 播种、浇水、成熟、施肥等状态更新不能覆盖丢失坐标信息。

摆摊与顾客

摆摊规则

  • 玩家在镇街可摆摊区域内交互开摊，定价范围仍是 1-5 元。
  • 摊位读取背包中的第一个可售商品，当前版本先支持单商品上架。
  • 摊位商品格数和影响范围来自摊位升级配置；不再设置总上架数量上限。
  • 开摊后生成三个关键节点：顾客影响范围 InfluenceArea、城管检测目标 InspectionTarget、玩家活动空气墙 PlayerBoundary。
  • InspectionTarget 的范围与摊位影响范围一致。
  • PlayerBoundary 使用玩家专用碰撞层，只限制玩家，不阻挡城管。

顾客规则

  • 顾客从居民区、学校、工厂之间按时间窗口移动，生成总数有限，生成时间随机。
  • 学生主要在 06:00-08:00 上学、16:00-18:00 放学。
  • 工人主要在 07:00-09:00 上班、17:00-19:00 下班。
  • 顾客进入摊位影响范围后，先按偏好判断是否停留，再按预算和价格判断是否购买。
  • 顾客决定购买时，会停留 5-10 秒并显示倒计时；玩家必须在倒计时结束前按 E 确认交易。

城管系统

发现与追逐

  • ChengguanSpawner 在城镇中随机生成城管，每天生成数量有限。
  • 城管巡逻时使用 DetectionArea(Area2D) 检测摊位的 InspectionTarget。
  • 发现摊位后不会立即处罚，而是记录违规成立并进入 chasing 状态追玩家。
  • 城管巡逻速度为 70，追击速度为 138，略快于玩家速度 120。
  • 抓捕判定由 CatchArea.body_entered 触发，不用逐帧距离判断。

处罚规则

  • 一旦城管发现摊位，违规记录成立。
  • 之后即使玩家已经收摊，只要被城管追到，仍然会罚款。
  • 如果被追到时摊位还开着，则罚款并强制收摊。
  • 如果摊位已经收了，则只罚款。
  • 罚款金额当前为 8 元，不会扣成负现金。
  • 日结统计会记录被抓次数和罚款总额。
这个系统的体验重点是“被发现后的紧张追逐”，不是发现瞬间的惩罚。后续需要实测追击速度、检测半径和生成频率，避免风险过高导致玩家不愿意摆摊。

商店与升级

小卖部 卖苹果种子，也会每天随机价格和库存直接卖苹果，支持玩家低买高卖。
背包升级 花钱增加背包格子数量。当前配置从 8 格升级到 12、16 格。
摊位升级 提高上架容量和影响半径。影响范围越大，顾客更容易被吸引，城管也更容易发现。

Node / Signal 设计摘要

Player移动、动画、交互检测。按最近可交互 Area2D 触发 interact(player)。
FarmField只在锄头状态下检测开垦交互，负责按 tile 生成动态 FarmPlot。
FarmPlot负责单格农田状态机：播种、浇水、成熟、收获。
Stall负责商品上架、库存、价格、影响范围、城管检测目标和玩家空气墙。
Customer负责顾客路线、偏好、预算、购买倒计时和成交确认。
Chengguan负责巡逻、发现摊位、追逐玩家和抓捕处罚。
SeedShop负责种子、每日苹果库存和升级入口。
HUD / Panels显示现金、时间、目标、工具、背包、商店、定价和日结。

关键 Signal

  • inventory_changed、backpack_changed：背包数量和格子 UI 更新。
  • cash_changed：现金 UI 更新。
  • current_tool_changed：工具切换，刷新农田可交互状态。
  • scene_change_requested：房屋、家、镇街之间切换。
  • price_panel_requested、shop_panel_requested：打开定价和商店面板。
  • sale_completed、customer_decision：交易结果反馈。
  • daily_summary_ready：显示昨日总结。
  • chengguan_penalty：记录并反馈城管处罚。

验收标准

  • 玩家从房屋出门会到房屋门口出生点，而不是镇街入口。
  • 玩家装备锄头时，院子可开垦区域才出现开垦交互。
  • 新开垦农田为 1x1 tile，位置与 TileMapLayer 对齐，开垦后直接可播种。
  • 玩家去镇街再回家，已开垦农田不会消失。
  • 背包满时购买、收获或进货不会静默丢物品。
  • 顾客购买需要玩家在倒计时内按 E 确认。
  • 城管发现摊位后追玩家，追到才罚款；已收摊也会处罚。
  • 摊位影响范围、城管检测目标和摊位升级数据保持一致。
  • 午夜或睡觉进入第二天，日结数据和作物成长正确推进。

测试计划

  • tests/config_inventory_v2_test.gd：配置读取、格子背包、堆叠和满包。
  • tests/farm_field_creation_test.gd：动态开垦、tile 对齐、锄头限定、场景重载恢复。
  • tests/farm_v2_test.gd：农田状态机和跨天成长。
  • tests/day_upgrade_chengguan_v2_test.gd：日结、升级、城管发现、追逐后处罚、已收摊仍处罚。
  • tests/player_stall_tether_test.gd：玩家空气墙、城管检测目标范围和摊位清理。
  • 每次关键改动后运行所有 tests/*_test.tscn，再做主场景 headless 加载。

全玩法范围补充

第二版的完成标准不是“新增几个系统”，而是把当前项目内所有核心玩法都设计清楚、接入闭环并完成验证。 下表作为第二版的玩法范围边界；未列入的内容默认不进入第二版，避免原型继续外扩。

种植玩法 覆盖开垦、播种、浇水、施肥、跨天成长、成熟、收获、满包失败、场景切换恢复和多作物配置。苹果若保持 growth_days=0，必须明确“一浇水即成熟”还是“隔天成熟”的最终规则。
库存玩法 覆盖格子容量、堆叠上限、购买入包、收获入包、开摊扣货、收摊返货、满包提示、升级扩容和 UI 图标显示。第二版不做拖拽整理，但必须保证不会静默丢物。
摆摊玩法 覆盖可摆摊点、定价、上架商品、库存上限、影响范围、玩家活动边界、成交确认、拒买反馈、售罄反馈和收摊返还。若仍只支持单商品上架，需要把“选择上架商品”列为第二版后续而不是验收必需。
顾客玩法 覆盖学生和工人的时间窗口、路线、预算、偏好、停留倒计时、玩家确认成交、超时离开和日结统计。顾客不能在场景切换后残留到错误父节点。
风险玩法 覆盖城管生成、巡逻、发现、追逐、抓捕、罚款、强制收摊、已收摊仍处罚和每日次数限制。风险必须能被玩家理解，并通过数值调校保持“紧张但不劝退”。
经济与成长 覆盖现金、商店每日价格和库存、低买高卖、种子购买、背包升级、摊位升级、罚款消耗和日结评价。至少要能形成 3-5 天的短期成长目标。
时间与日结 覆盖 06:00 开始、时段切换、午夜强制结算、床上主动睡觉、作物成长推进、商店刷新、日统计归零和昨日总结展示。

还需要补充的设计

1. 新手引导与目标链

  • 需要写清楚第一天玩家看到的目标顺序：出门、开垦、播种、浇水、买货、去镇街、开摊、确认交易、回屋睡觉。
  • 每个目标都要有失败提示，例如没钱、没种子、没货、背包满、工具不对、摊位已开、顾客超时离开。
  • HUD 目前显示目标文本，但方案里还缺“目标如何推进、何时替换、哪些目标不应覆盖”的规则。

2. 商店商品列表

  • 当前商店只稳定支持苹果种子和每日苹果；如果第二版目标是验证全部玩法，建议商店至少能从 crops.json 生成种子列表。
  • 需要决定每种种子的价格来源：继续使用常量、写入 items.json，或新增商店配置。推荐把购买价格放入配置，避免售价、进价和种植收益散落在脚本里。
  • 需要明确肥料的获得方式、价格和每日库存，否则施肥只是系统入口，不是完整玩法。

3. 商品选择与价格策略

  • 第二版若要验证多作物经营，摊位应支持选择上架商品；否则多作物只能被种出来，不能形成明确经营策略。
  • 价格范围现在仍是 1-5 元，适合苹果，但不一定适合梨、黄瓜、番茄等作物。需要定义按商品基础售价计算的定价范围。
  • 顾客偏好应至少覆盖全部可售作物，避免新作物永远卖不出去或都按苹果逻辑成交。

4. 失败、惩罚与恢复

  • 需要明确现金为 0、背包满、没有种子、没有商品、被城管罚光钱、午夜未回家时玩家如何继续玩。
  • 建议第二版不设置硬失败结局，但必须保证玩家始终能通过免费或低成本路径重新进入经营循环。
  • 日结中应区分“拒买”和“错过确认”，否则无法判断是定价问题还是玩家操作问题。

5. 存档与重开规则

  • 现有状态主要在 GameState 内存中流转；若第二版要验证多日玩法，至少需要明确本阶段是否必须落盘保存。
  • 如果不做正式存档，也要补充“重启游戏从第 1 天开始”的原型限制，避免误以为多日进度已经可靠持久化。

验证矩阵补充

自动化测试必须覆盖 配置加载、背包堆叠和满包、农田动态创建和恢复、跨天成长、顾客购买确认、商店随机库存、升级、城管追逐处罚、摊位边界清理、日结统计。
手动验证必须覆盖 完整跑通至少 3 个游戏日：第 1 天卖苹果，第 2 天完成种植收获，第 3 天升级背包或摊位，并至少经历一次城管追逐。
平衡验证必须记录 每日平均收入、平均成交数、拒买率、错过率、城管触发率、罚款占收入比例、首次升级所需天数、背包满发生次数。
主场景验收 scenes/main.tscn 可 headless 加载；玩家能从房屋到院子到镇街再回屋；所有 UI 面板可打开关闭；没有启动时报错、空引用或无法退出的阻塞状态。

第二版退出标准

  • 所有“全玩法范围补充”中的系统都有明确设计、实现入口和至少一条验证路径。
  • 玩家可以连续游玩 3 天以上，并经历种植、购买、摆摊、成交、拒买、罚款、升级和日结。
  • 全部 tests/*_test.tscn 通过，主场景能无错误加载。
  • 设计文档中的“后续迭代”只保留体验增强项，不再包含第二版闭环必需项。
  • 已知限制被写入文档，例如是否暂不支持正式存档、是否暂不支持拖拽整理背包、是否暂不支持多商品同时上架。

后续迭代

  • 把苹果 growth_days=0 时“一浇水就成熟”的逻辑接入 FarmPlot。
  • 增加工具 UI，让当前工具和快捷键更直观。
  • 摊位支持玩家选择上架商品，而不是默认背包中第一个可售商品。
  • 优化城管追逐：加入警告时间、视线遮挡、逃脱距离或躲避点。
  • 商店扩展为作物种子列表，并读取配置生成购买按钮。
  • 建立正式存档结构，把 GameState 中的动态农田、背包、升级和日期写入保存文件。
